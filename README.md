# Gestão Hospitalar for RESTgym

This repository is the RESTgym integration of Gestão Hospitalar. It is meant to be used as a Git submodule of [RESTgym](https://github.com/restgym/restgym) (in `apis/gestao-hospital/`), which builds its Docker image and runs it with the testing tools: it does not work on its own.

## The API

| | |
|---|---|
| Name | Gestão Hospitalar |
| Version | 0.0.1 |
| Description | Hospital management system (hospitals, patients, beds and stock), from the Codenation AceleraDev challenge. |
| Domain | Healthcare |
| License | Not declared |
| Original repository | https://github.com/ValchanOficial/GestaoHospital, also included in the [WebFuzzing Dataset (EMB)](https://github.com/WebFuzzing/Dataset) |
| Technology | Java 8, Spring Boot 2.1.3, MongoDB 6.0 |
| Original specification | Swagger 2.0, JSON, generated by springfox 2.6.1, served by the API at `/v2/api-docs` |

| External services | LocationIQ (`https://us1.locationiq.com/v1/search.php`, with a key hard-coded upstream): `POST /v1/hospitais/` geocodes the address of the new hospital |

More details (e.g., how 5XX responses are grouped into unique failures) are in the manifest, `restgym-api-manifest.yaml`.

## How RESTgym runs it

The image starts from the base image of RESTgym for Java 8 (`restgym/api-base:java8`), which contains the proxy and the collection of code coverage. MongoDB runs in the container, and is initialized with `database/init-mongo.js` at each start. Creating a hospital calls an external service, so the container has internet access (`requirements.internet` in the manifest). The tools reach the API through the proxy of RESTgym, on port 9090.

## Changes made by RESTgym

### API

None.

### Specification

The original specification is `swagger-original.json` (Swagger 2.0): the specification that the API serves at `/v2/api-docs` (springfox 2.6.1), saved unchanged from the API running in its RESTgym container (2026-10-13). `gestao-hospital-openapi.json` and `gestao-hospital.yaml`, given to the tools, have the same content: the conversion of the original to OpenAPI 3.0.1, with nothing else changed (the same operations, parameters, request bodies, responses and schemas).

### Integration

- The proxy does not authenticate requests (until 2026-10-11 it tried to register a user before every request, although the API has no authentication).

## Endpoints that may interfere with authentication

RESTgym handles the authentication of the requests, and the tools are not aware of it: an endpoint that ends or changes the session of RESTgym (e.g., logout, login as another user, change or deletion of the user of the proxy, of its password or of its roles) may make the tools fail for the rest of the run. Such endpoints may be removed from the specifications given to the tools.

None: RESTgym does not authenticate the requests to this API (it needs no authentication), so no endpoint can end or change a session of RESTgym.

## Known issues

- **LocationIQ rate-limits the hard-coded key**, shared by all the runs: hospitals are created only while the key works, and results depend on the service.
