## Standardized specification

`standardized/gestao-hospital-swagger.json`: the original, formatted (indented with 2 spaces; the original is minified, on one line). `standardized/gestao-hospital-swagger.yaml` is the same specification in YAML, converted with yq 4.44.3 (the same content and order of properties, checked; see §6.4 of `docs/API-INTEGRATION-PROTOCOL.md` in RESTgym). The OpenAPI 3 version is converted from it (see below).

Changes from the original (otherwise the same content, with the keys in the same order):

- **`schemes: ["http"]` added** (full URL of the API, rule 5 of the standardization): the original has `host: localhost:8080` and `basePath: /`, but no `schemes`, so it does not state the scheme of the API. Swagger 2.0 then takes the scheme with which the specification was fetched, which a tool that reads it from a file does not have, and its conversion to OpenAPI 3 has the server `//localhost:8080/`, without scheme. The API in its RESTgym container is served only over HTTP (port 8080, no TLS), as `schemes` now states (the same as Flowable).

**OpenAPI 3 version** (`standardized/gestao-hospital-openapi.json`, and `standardized/gestao-hospital-openapi.yaml`, the same in YAML): converted from `standardized/gestao-hospital-swagger.json` with the official Swagger Converter (swagger-converter 1.0.5, `POST /api/convert`); its output, minified, is only indented with yq 4.44.3, and its YAML version is converted with yq (see §6.4 of `docs/API-INTEGRATION-PROTOCOL.md` in RESTgym). Nothing is edited by hand. Checked against the Swagger version: the same 20 operations, with the same parameters (name, location, required), request bodies and response codes, and the same 6 schemas, in the same order; it passes the official validation. What the conversion changes: `host`, `basePath` and `schemes` become the server `http://localhost:8080/` (the converter always ends it with `/`: a tool that joins it with a path without removing one of the two slashes would request, e.g., `http://localhost:8080//...`); `definitions` become `components/schemas`; the body parameters become request bodies; `consumes` and `produces` become the media types of the request bodies and of the responses; and the converter adds `x-original-swagger-version: "2.0"`. Nothing is lost: every feature of the Swagger version has an equivalent in OpenAPI 3.

The official validation passes: `standardized/validation.json` (2026-10, swagger-validator-v2 2.1.9) has no messages.
